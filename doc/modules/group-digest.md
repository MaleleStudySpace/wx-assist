# 群聊定时摘要

## 1. 用户视角

用户在群聊助手中创建摘要分组，选择一个或多个会话、回溯范围、触发时间和摘要风格。到点后系统读取新消息，使用 AI 生成摘要，写入通知队列，并投递到已绑定的通知渠道。

## 2. 业务流程

```text
配置摘要分组
  → DigestScheduler 每分钟检查
  → 收集分组内会话消息
  → 过滤噪音、媒体和不可读内容
  → 选择 single / packed / per_chat 模式
  → AI 生成摘要
  → 更新分组记忆（可选）
  → 写入通知队列和任务中心
  → 投递到已绑定渠道
```

分组内只有一个有内容的会话时使用 single；消息量合适时使用 packed；超出预算或 Provider 拒绝时按会话降级为 per_chat，再拼接结果，不再额外调用一次总合并。

## 3. 配置字段

| 字段 | 说明 |
|---|---|
| 分组名称 | 展示名称 |
| 会话列表 | 分组内要摘要的聊天会话 |
| `cron_expr` | 日内 cron，可多行 |
| `schedule` | 兼容的时间列表，cron 优先 |
| 回溯范围 | 最近若干小时或自动推算 |
| 摘要风格 | 行动项优先、完整复盘、极简速览或自定义 |
| 未读模式 | 只处理未读消息 |
| 记忆开关 | 是否更新分组长期记忆 |
| 推送开关 | 是否发送到已绑定渠道 |

旧版本的单会话字段会在加载时迁移为分组模型。`schedule` 与 `cron_expr` 可以同时保存，实际执行时 cron 优先、schedule 回退。

## 4. 消息预处理

摘要不会直接把所有原始消息交给 AI，而会先：

- 去掉系统消息、极短回复和常见噪音；
- 将图片、语音、视频、表情等转换为简洁占位；
- 清理 XML 或内部标识符；
- 按时间排序并按预算裁剪较早消息；
- 对部分失败的会话单独记录，不影响其他会话继续生成。

## 5. 失败与降级

| 情况 | 行为 |
|---|---|
| 窗口内没有新消息 | 记录一次无新内容，不发送推送 |
| 某会话读取失败 | 记录失败会话，其他会话继续 |
| 全部会话读取失败 | 任务失败，不伪装成无新内容 |
| AI 未配置 | 任务失败并提示配置 AI |
| Provider 上下文超限 | 切换逐会话模式 |
| 没有绑定通知渠道 | 任务可完成，推送状态为跳过 |

## 6. 记忆

分组维护一份可持续更新的摘要记忆。记忆更新走独立的持久化接口，避免 Web 配置保存和后台任务同时写入时互相覆盖。
